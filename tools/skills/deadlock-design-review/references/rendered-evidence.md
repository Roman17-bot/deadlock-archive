# Rendered, interaction and performance evidence

Review only the assigned surface. Obtain equal-state before/after views: route, data version, language, theme, viewport, scroll position and selected/open states. If these differ, name the mismatch and limit the comparison. Screenshots support visible appearance; live behavior supports interaction claims; source supports implementation findings. Keep those evidence types distinct.

With assigned browser ownership, exercise the meaningful states: normal/selected/pressed/focus/disabled, long RU/EN labels, narrow/wide layouts and relevant empty/loading/error content. Verify overflow, table scrolling and sticky behavior in the browser. Follow the available computer-use skill/tool rules. In read-only mode do not persist screenshots, traces or reports; inspect tool-returned views or coordinator-supplied artifacts and return their identifiers in report text. Do not invoke production mutations or modify the page to force a desired result. The coordinator can supply an isolated prototype or collect persistent evidence.

For motion, observe the actual trigger at normal speed, replay, quick interruption/repeated input, keyboard/touch and reduced motion when available. Check focus stability, immediate data/action response and whether motion clarifies this particular control. A midpoint still proves only that pictured state. Source inspection may reveal missing cleanup but does not establish smoothness or successful execution.

For Canvas/WebGL/3D, check static fallback and reduced motion, native scrolling, visibility/idle rendering, context failure/loss handling and cleanup. Distinguish source-supported lifecycle risks from failures reproduced live. If performance is material, request or inspect bounded timing/paint/frame evidence with browser/device, workload and method. Attribute traces supplied by others; do not call them your own measurements. Unit-test counts do not prove rendering quality or FPS. No available live or profiling tool means a stated limit, not an assumed pass or invented blocker.

Report observed defect, consequence and smallest scoped correction. Mark preferences as suggestions. Block on material unreadability, lost actions, serious layout drift or reproduced performance/accessibility failures. Do not turn every unchecked possibility into a finding. Zero findings is valid; unavailable checks remain explicit. Hand the coordinator a bounded next pass tied to the evidence that would resolve the remaining question.
