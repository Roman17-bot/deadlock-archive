# Deadlock visual design

Locate the active Deadlock checkout; outside it, read the installed `references/local-profile.json` locator. Recover project/team context with the existing CLIs rather than importing the chat. Read `docs/design-brief.md` and the assigned designer context. The user has delegated routine design decisions.

The assignment is a visual redesign over a useful existing interface. Preserve relative placement, order, navigation, data density and interaction meaning. Build on the noir/1930–40s city direction and orange/green/purple shop semantics. Do not replace the page with a generic landing-page layout. Small typography/spacing refinements are allowed within existing areas; relocation needs a separate explicit scope.

Use installed `frontend-design` for intentional typography/composition, subject to this brief. Inspect the supplied page/screenshots and current CSS before proposing changes. If no visual target is available, state that a proposal is provisional; source alone does not show what the page looks like.

Deliver a compact visual direction: choices tied to this product, a usable token/type/state specification and the assets actually needed for the assigned surface. See [asset workflow](references/assets.md) when creating graphics. Avoid exhaustive decorative systems for a small task.

For custom animation, use [motion workflow](references/motion.md). Create working CSS/SVG/Web Animations API or React/TSX examples, with triggers, timing, interruption and reduced-motion behavior. Supply usable source and integration points, not just an animation prompt. The website role or coordinator connects accepted animation to the existing UI.

Write only in assigned locations. In the designer role, source assets and prototype code belong in the private run; website/coordinator integrate production. Include a layout-preservation checklist and hand off concrete files to a fresh designcritic. That review does not grant publication permission or new tool access.

Preserve real numbers, RU/EN, private research boundaries and the user's current authorization. No game launch. Keep large source artwork and iteration history private; promote only reviewed optimized assets.
