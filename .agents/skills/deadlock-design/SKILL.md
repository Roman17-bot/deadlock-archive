# Deadlock visual design

Locate the active Deadlock checkout; outside it, use the installed deadlock-project locator. Recover project/team context with the existing CLIs rather than importing the chat. Read `docs/design-brief.md`, `docs/design-system.md` and the assigned designer context. The selected Heritage green/ivory/gold direction is the default. Routine design decisions are delegated.

The assignment is a visual redesign over a useful existing interface. Preserve relative placement, order, navigation, data density and interaction meaning. Build on the noir/1930–40s city direction and orange/green/purple shop semantics. Do not replace the page with a generic landing-page layout. Small typography/spacing refinements are allowed within existing areas; relocation needs a separate explicit scope.

Inspect supplied pages/screenshots and current CSS before proposing changes. If no rendered target is available, mark the proposal provisional. Use available project-local `frontend-design` for typography/composition; read `ui-ux-pro-max` only for a specific unresolved UX question. For shader work use available `shader-dev` and [creative graphics](references/creative-graphics.md). Do not load every skill or change the React/CSS stack to fit examples from one.

Choose an art direction tied to this product and explain its distinctive craft through lettering, graphics, material or interaction, beyond palette and ornament. Deliver only the token/type/state specification and assets needed for the assigned surface. See [asset workflow](references/assets.md) for graphics, [creative graphics](references/creative-graphics.md) for Canvas/WebGL/3D, and `docs/design/CREATIVE_DIRECTION.md` for the iteration handoff.

For custom animation, use [motion workflow](references/motion.md). Create working CSS/SVG/Web Animations API or React/TSX examples, with triggers, timing, interruption and reduced-motion behavior. Supply usable source and integration points, not just an animation prompt. The website role or coordinator connects accepted animation to the existing UI.

Write only in assigned locations. Source assets and runnable prototypes belong in the private run; website/coordinator integrate production. For assigned browser work, use the available project Playwright/DevTools MCP bindings described in `docs/design/TOOLS_AND_SKILLS.md`; keep existing computer-use as a fallback. Hand off concrete files, layout anchors, actual browser checks and material blockers to a fresh designcritic. Iterate against observed findings with a bounded next scope; cosmetic churn is not evidence of improvement. Review grants neither publication permission nor new tool access.

Preserve real numbers, RU/EN, private research boundaries and the user's current authorization. No game launch. Keep large source artwork and iteration history private; promote only reviewed optimized assets.
