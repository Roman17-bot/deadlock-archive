# Creative graphics and spatial work

Read for a task that benefits from original SVG, Canvas, shaders, WebGL or 3D. Choose the lightest medium that expresses a specific idea: editable SVG for marks and precise line work; Canvas for dense procedural drawing; WebGL/3D for a meaningful spatial or material relationship. A spinning emblem or ambient particle field alone does not justify a renderer. Typography, composition and small SVG craft can carry a stronger direction than a scene.

Keep Heritage and the current layout as anchors. A city archive seal, engraved instrument or occult diagram must help recognition, hierarchy or feedback rather than fill empty space. Explain what belongs specifically to this product and show the artifact at its real display size. Preserve HTML labels, real game values, keyboard focus and accessible controls outside the drawing surface.

Use existing tools and dependencies first. Read available `shader-dev` only for shader work; verify unfamiliar API support against primary documentation when needed. A prototype is not authorization to install a renderer or migrate the application. Give website a compact integration boundary, loading strategy and dependency/asset cost if a new dependency is proposed.

For a spatial effect, deliver runnable editable sources and a private preview, camera/material/light choices, responsive bounds and input behavior. Include the motion contract from [motion.md](motion.md): trigger, timing, replay, interruption and reduced motion. Keep native scrolling and gestures intact; hover cannot be the only way to reveal useful content. Render only while visible and active, stop idle frame loops, cap pixel density where appropriate, resize without layout churn and release listeners, animation frames, geometries, materials, textures and contexts owned by the component on disposal. Address WebGL context loss/restoration and failure to create a context with a usable static SVG/image/CSS fallback. Reduced motion must preserve information without camera travel or perpetual motion.

Choose a performance budget proportional to the surface before integration: added transfer size, initialization cost, active/idle rendering and representative device/viewport. Record what was measured, device/browser, method and limits. Do not infer frame rate from a screenshot or claim an untested device. A fallback is part of the deliverable, not a future task. Keep source artwork, experiments and licenses/generation provenance private; promote only reviewed optimized outputs.
