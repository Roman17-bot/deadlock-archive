# Graphics and icon handoff

Choose a format for the actual job. Extend the current ArchiveIcons SVG system for UI glyphs; use existing symbols where they fit and original geometry where it improves recognition; keep a shared viewBox/stroke rhythm, recognizable silhouettes, clear optical bounds and a currentColor/themed fallback. Test at intended CSS size, not only enlarged. Keep semantic labels in React; decorative artwork must not become an extra screen-reader announcement.

Use the available imagegen skill/tool for new raster illustrations or texture work, and for raster edits. Read its current instructions when applying it. Inspect local reference images first; preserve requested transparency and original input assets. Do not claim that an image was generated or edited if only a prompt was drafted. If the tool is unavailable, prepare an honest brief or use code-native artwork when that fits; do not silently substitute an unapproved remote service.

For each accepted asset keep: source editable file, intended role and size, theme variants if needed, optimization target, origin/license or generation record, and a preview at normal size. Keep this record in the private run or project asset documentation; the public interface does not need source badges.

Avoid embedding labels, game numbers or critical explanations in generated imagery. Inspect exported alpha, edges, small-size legibility and visual weight. Large texture/illustration sources remain private; only optimized deliverables are proposed for public assets. Do not fetch/install fonts or image tooling just to make a moodboard when existing tools suffice.

For procedural or spatial artwork, read [creative-graphics.md](creative-graphics.md) only when relevant.
