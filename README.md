# Deadlock Archive

Независимый справочник Deadlock: главная, реестр героев, механики с калькуляторами и центр обновлений. Снимок **44 героев**, включая Nurse Harrow и Violet, проверен **25 октября 2026**, клиент **6819**. Число героев и версия в интерфейсе берутся из данных.

## Что работает

- Поиск по английским именам и русским вариантам.
- Сортировка каждого числового столбца в обе стороны.
- Уровни1–36 с индивидуальными приростами и встроенными Spirit-скейлами.
- Урон выстрела, расчётный DPS, HP, Spirit, регенерация и приросты за уровень.
- Примечания к особому оружию, источники и методика, CSV текущего результата.
- Крупные шрифты и элементы управления; полная таблица прокручивается вместе со страницей.
- На узких экранах столбцы прокручиваются горизонтально, имя героя закреплено.
- На телефонах компактные режимы «Характеристики» и «Приросты за LVL»; примечания открываются нажатием на героя. CSV сохраняет все показатели выбранных героев.
- Справочник из27 правил с43 источниками и15 режимами калькулятора: EHP, урон, лечение, вампиризм, длительность, CDR, дальность, HP и другие.
- Владелец обновляет локальные данные и отправляет публикацию одной кнопкой. Источники проверяются по версии и raw-файлам; ошибочный кандидат не заменяет рабочие данные.
- Приватный SQLite/FTS5 индекс исследований и устанавливаемый навык для восстановления контекста проекта.
- Локальная PostgreSQL: герои, оружие, механики RU/EN, источники и история снимков; миграции, резервные копии и проверяемый экспорт.
- RU/EN на всех страницах, включая заметки, формулы, калькуляторы и скачиваемый разбор. Язык сохраняется в браузере; форматы дат/чисел и заголовки CSV следуют выбранному языку.

## Локальный запуск

Нужен **Node.js24.15+ LTS** и npm.

```sh
npm ci
npm run dev
```

`npm run dev` запускает сайт и Node.js API вместе, ждёт готовности обоих и автоматически открывает главную страницу в новой вкладке **Google Chrome**. `Ctrl+C` останавливает оба сервиса. После первого `npm ci` для ежедневного запуска нужна только эта одна команда.

Сайт: http://127.0.0.1:5173/ . Node.js API: http://127.0.0.1:3001/api/heroes . Проверка API: /api/health . Сервер слушает только loopback. Локальная разработка читает живой API через Vite proxy; GitHub Pages читает статический снимок. После обновления локальный API использует новые данные без перезапуска.

При настроенном `.env.local` API читает PostgreSQL. Первый запуск заполняет только пустую БД; существующие записи не заменяются файлами при перезапуске. Ошибка подключения показывается явно. Без конфигурации БД проект работает с JSON, в том числе на GitHub Pages и в обычной CI-сборке.

```sh
npm run db:status
npm run db:backup
```

На новом компьютере с PostgreSQL сначала выполни `npm run db:setup`: пароль администратора вводится скрыто, для приложения создаётся отдельная роль и приватный конфигурационный файл. Подробные команды, схема и подключение VS Code — в [docs/database.md](docs/database.md).

```sh
npm test
npm run typecheck
npm run data:check
npm run build
npm run preview
```

Для отдельного запуска: npm run dev:web или npm run dev:api. Порт API меняется через API_PORT (прокси использует то же значение). Если Chrome установлен в другом месте, задай CHROME_PATH полным путём к исполняемому файлу. NO_OPEN=1 отключает только автооткрытие браузера, например на сервере разработки.

## Архитектура

```text
data/          проверенный публичный JSON и происхождение данных
db/            SQL-миграции и примеры запросов
server/database/ PostgreSQL: конфигурация, транзакционный импорт и чтение
shared/        типы, формулы уровней, поиск, сортировка, CSV
server/        Node HTTP API; отдельно тестируемый createApp
src/app/       маршруты, загрузка и состояния приложения
src/pages/     главная
src/features/  таблица, механики/калькуляторы, центр обновлений
src/components/ диалог методики
src/i18n/      i18next/react-i18next, словари интерфейса и заметок RU/EN
src/styles/    обычный CSS: общие стили, главная, реестр
public/assets/ локальные портреты и шрифты
server/updates/ получение, сверка, резервирование, owner API, запуск публикации
scripts/       проверка, обновление, SQLite index и установка навыка
tools/skills/  поддерживаемый исходник навыка deadlock-project
tests/         тесты пользовательских сценариев
```

Публичные изменения проходят через проверенный пакет `data/`; `public/data/` генерируется перед запуском и сборкой. Локальное рабочее хранилище — PostgreSQL. Импорт сохраняет полный снимок одной транзакцией и переключает текущую версию только после успеха. `db:export` создаёт отдельную папку для проверки, без публикации и перезаписи `data/`. Типы — в `shared/`, расчёты — в `shared/heroes.ts` и `shared/mechanics.ts`. Значения сохраняются с исходной точностью, округляется только вывод.

## Значение характеристик

LVL1 соответствует0Boons, каждый следующий уровень — ещё1Boon; максимум36/35. Spirit растёт индивидуально. Victor получает регенерацию через Spirit, Vindicta/GreyTalon/Solomon — дополнительный урон оружия. Warden имеет два представления одного скейла скорострельности, которые не складываются дважды.

Урон выстрела суммирует обычные попавшие дробины. Для hit-once несколько траекторий дают один урон по цели: Baba8,8 и Drifter19,5 на LVL1; прежнее умножение на3 исправлено. У очередей показан отдельный выстрел. Расчётный DPS исключает перезарядку, сопротивления, дистанцию, хедшоты, предметы и активные эффекты. Интервал сравнительной модели: cycle + (burst−1)×intraBurst; другие трактовки burst описаны в механиках. Движок не измерялся. У раскручивающегося оружия показан стартовый DPS.

Источник: [версия клиента](https://api.deadlock-api.com/v1/assets/steam-info), [герои6819](https://api.deadlock-api.com/v1/assets/heroes?client_version=6819), [оружие6819](https://api.deadlock-api.com/v1/assets/items?client_version=6819), [фиксированная ревизия игры](https://github.com/SteamTracking/GameTracking-Deadlock/tree/17462b250a0ca80e7f80102f2c83cc3eecff5f12).

## Обновление данных и синхронизация

В локальном сайте открой `#/updates`. Кнопка **«Обновить данные»** проверяет версию игры: при совпадении клиента полные данные, файлы, индекс и GitHub Actions не обновляются. Новый клиент проходит сверку version-pinned API/raw-источников, сохраняется в JSON и PostgreSQL. Перед обновлением текущие механики и история из БД переносятся в рабочие файлы. При включённом **«Опубликовать после сохранения»** публикуется точный итоговый снимок PostgreSQL.

Для правок внутри той же версии клиента используй **«Синхронизировать с Pages»** в отдельной карточке. Она сравнивает содержимое, а не только номер патча: все пять публичных JSON, портреты и стабильный манифест SHA256. Снимок читается одной транзакцией, проверяется, сохраняется локально с резервными копиями, затем одним коммитом передаётся в GitHub. Сборка использует именно эти данные. Статус **«синхронизированы»** появляется после проверки реальных файлов на Pages. Если всё уже совпадает, новый коммит и Actions не создаются.

```sh
npm run data:update -- --dry-run
npm run data:update
npm run db:sync -- --dry-run
npm run db:sync -- --wait
```

`data:update` обновляет локальные JSON/БД; `db:sync` публикует текущий снимок БД. `--dry-run` не записывает данные, состояние или коммиты; `--wait` ждёт подтверждённого развёртывания до десяти минут. Обычная команда без `--wait` возвращает статус очереди, позднее её можно повторить с `--wait`: сохранённая задача будет проверена и продолжена. Прерванная/неудачная сборка повторяется для того же коммита без дублирования данных. Более новый снимок на GitHub и конкурентное изменение ветки не перезаписываются автоматически.

Сохранение JSON, импорт PostgreSQL, приватная индексация, коммит GitHub и развёртывание Pages — разные результаты. Сбой импорта сохраняет предыдущую версию в БД и блокирует публикацию; после восстановления можно повторить обновление или отдельно выполнить `npm run db:import`. Сбой публикации не удаляет локальный снимок: повтор выполняется кнопкой синхронизации. Резервные копии находятся в приватной `work/backups/`.

История содержит версию клиента, дату сборки и дату первого появления в архиве. Исходная запись6819 подтверждена первым коммитом данных; фиктивных прошлых версий нет. Локальный API читает историю из БД, Pages — из опубликованного снимка. Формулы сохраняют реальную версию последней сверки: новый патч героев не делает их автоматически перепроверенными.

GitHub Actions больше не получает игровые данные заново при публикации. `pages.yml` собирает переданный коммит; ручной [Publish stored snapshot](https://github.com/Roman17-bot/deadlock-archive/actions/workflows/refresh-data.yml) повторно публикует уже сохранённые данные репозитория. Перед сборкой и непосредственно перед развёртыванием проверяется актуальность коммита, чтобы старый повтор не откатил сайт. Токен GitHub остаётся в локальном сервере через существующий Credential Manager и не попадает в React, localStorage, журналы или JSON.

На публичном сайте **«Проверить обновления»** загружает опубликованный снимок и сравнивает доступную версию игры. Для отправки изменений из PostgreSQL нужен работающий локальный сервер или CLI на компьютере владельца. После публикации друзьям работающий ПК не требуется. Прямые изменения SQL не отправляются фоновым наблюдателем: их публикуют явной синхронизацией, чтобы незавершённые правки не попадали на сайт.

Источники игры — поддерживаемые сторонние извлечения файлов Valve. При несовпадении версий, неизвестной схеме или механике обновление останавливается, сохраняя рабочие данные. Подробнее о БД, подключении VS Code и командах — [docs/database.md](docs/database.md).

## База знаний и навык

```sh
npm run knowledge:import
npm run knowledge -- status
npm run knowledge -- search "вампиризм" --limit 5
npm run knowledge -- formula lifesteal-amp
npm run skill:install
```

База `knowledge/archive.sqlite` остаётся приватной. История и источники сохраняются; raw способности/предметы считаются текущими только для совпадающей версии героев. Если нового raw cache нет, статус это показывает, старые записи доступны через `--history`. Навык устанавливается в пользовательскую папку Codex; подробнее [docs/knowledge.md](docs/knowledge.md).

Для текущих данных сайта доступны короткие запросы PostgreSQL: `npm run db:query -- hero "Nurse Harrow"` и `npm run db:query -- formula resistance ru`. Исследования и решения по проекту извлекаются из отдельного SQLite-архива. Для расчётов используется тот же проверенный модуль `shared/mechanics.ts`, что и в калькуляторе сайта.

## Публикация

GitHub Actions проверяет данные, тестирует и собирает сайт на Node24, затем публикует dist в GitHub Pages. VITE_BASE_PATH задаётся как /имя-репозитория/. Hash-маршруты #/, #/heroes, #/mechanics и #/updates работают без серверных перенаправлений. Статические данные и ресурсы используют тот же base path.

GitHub Pages не запускает Node.js: публичная версия работает с JSON. API остаётся готовым для будущего размещения на Node-сервере. Полные личные исследования, исторические журналы матчей и рабочие файлы хранятся в ignored knowledge/, outputs/ и work/, не загружаются в публичный репозиторий.
