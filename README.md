# Deadlock Archive

Независимый справочник Deadlock: главная, реестр героев, механики с калькуляторами и центр обновлений. Снимок **44 героев**, включая Nurse Harrow и Violet, проверен **25 октября 2026**, клиент **6819**. Число героев и версия в интерфейсе берутся из данных.

## Что работает

- Поиск по английским именам и русским вариантам.
- Сортировка каждого числового столбца в обе стороны.
- Уровни1–36 с индивидуальными приростами и встроенными Spirit-скейлами.
- Урон выстрела, расчётный DPS, HP, Spirit, регенерация и приросты за уровень.
- Примечания к особому оружию, источники и методика, CSV текущего результата.
- Крупные шрифты и элементы управления; полная таблица прокручивается вместе со страницей.
- На узких экранах столбцы прокручиваются горизонтально, имя героя закреплено.
- На телефонах компактные режимы «Характеристики» и «Приросты за LVL»; примечания открываются нажатием на героя. CSV сохраняет все показатели выбранных героев.
- Справочник из27 правил с43 источниками и15 режимами калькулятора: EHP, урон, лечение, вампиризм, длительность, CDR, дальность, HP и другие.
- Владелец обновляет локальные данные и отправляет публикацию одной кнопкой. Источники проверяются по версии и raw-файлам; ошибочный кандидат не заменяет рабочие данные.
- Приватный SQLite/FTS5 индекс исследований и устанавливаемый навык для восстановления контекста проекта.
- RU/EN на всех страницах, включая заметки, формулы, калькуляторы и скачиваемый разбор. Язык сохраняется в браузере; форматы дат/чисел и заголовки CSV следуют выбранному языку.

## Локальный запуск

Нужен **Node.js24.15+ LTS** и npm.

```sh
npm ci
npm run dev
```

`npm run dev` запускает сайт и Node.js API вместе, ждёт готовности обоих и автоматически открывает главную страницу в новой вкладке **Google Chrome**. `Ctrl+C` останавливает оба сервиса. После первого `npm ci` для ежедневного запуска нужна только эта одна команда.

Сайт: http://127.0.0.1:5173/ . Node.js API: http://127.0.0.1:3001/api/heroes . Проверка API: /api/health . Сервер слушает только loopback. Локальная разработка читает живой API через Vite proxy; GitHub Pages читает статический снимок. После обновления локальный API использует новые данные без перезапуска.

```sh
npm test
npm run typecheck
npm run data:check
npm run build
npm run preview
```

Для отдельного запуска: npm run dev:web или npm run dev:api. Порт API меняется через API_PORT (прокси использует то же значение). Если Chrome установлен в другом месте, задай CHROME_PATH полным путём к исполняемому файлу. NO_OPEN=1 отключает только автооткрытие браузера, например на сервере разработки.

## Архитектура

```text
data/          единственный исходный JSON + происхождение данных
shared/        типы, формулы уровней, поиск, сортировка, CSV
server/        Node HTTP API; отдельно тестируемый createApp
src/app/       маршруты, загрузка и состояния приложения
src/pages/     главная
src/features/  таблица, механики/калькуляторы, центр обновлений
src/components/ диалог методики
src/i18n/      i18next/react-i18next, словари интерфейса и заметок RU/EN
src/styles/    обычный CSS: общие стили, главная, реестр
public/assets/ локальные портреты и шрифты
server/updates/ получение, сверка, резервирование, owner API, запуск публикации
scripts/       проверка, обновление, SQLite index и установка навыка
tools/skills/  поддерживаемый исходник навыка deadlock-project
tests/         тесты пользовательских сценариев
```

Изменения вносятся в data/heroes.json; public/data/ генерируется перед запуском и сборкой и не является вторым источником. Типы в shared/types.ts, расчёты — shared/heroes.ts. Значения сохраняются с исходной точностью, округляется только вывод.

## Значение характеристик

LVL1 соответствует0Boons, каждый следующий уровень — ещё1Boon; максимум36/35. Spirit растёт индивидуально. Victor получает регенерацию через Spirit, Vindicta/GreyTalon/Solomon — дополнительный урон оружия. Warden имеет два представления одного скейла скорострельности, которые не складываются дважды.

Урон выстрела суммирует обычные попавшие дробины. Для hit-once несколько траекторий дают один урон по цели: Baba8,8 и Drifter19,5 на LVL1; прежнее умножение на3 исправлено. У очередей показан отдельный выстрел. Расчётный DPS исключает перезарядку, сопротивления, дистанцию, хедшоты, предметы и активные эффекты. Интервал сравнительной модели: cycle + (burst−1)×intraBurst; другие трактовки burst описаны в механиках. Движок не измерялся. У раскручивающегося оружия показан стартовый DPS.

Источник: [версия клиента](https://api.deadlock-api.com/v1/assets/steam-info), [герои6819](https://api.deadlock-api.com/v1/assets/heroes?client_version=6819), [оружие6819](https://api.deadlock-api.com/v1/assets/items?client_version=6819), [фиксированная ревизия игры](https://github.com/SteamTracking/GameTracking-Deadlock/tree/17462b250a0ca80e7f80102f2c83cc3eecff5f12).

## Обновление данных

В запущенном локальном сайте открой `#/updates` и нажми **«Обновить данные»**. Сначала выполняется короткая проверка версии клиента. Если версия совпадает с локальной, результат — **«Текущая версия актуальна»**: полные данные не загружаются, файлы и индекс не перезаписываются, GitHub Actions не запускается. Флажок **«Опубликовать после сохранения»** включён по умолчанию. Для нового клиента кнопка получает свежие version-pinned API/raw данные, сверяет их, создаёт резервные копии при изменении и запускает `refresh-data.yml` через существующий Git Credential Manager. Токен не попадает в React, localStorage, журналы или JSON.

История на этой странице читает `data/version-history.json`: версия клиента, дата его сборки и дата первого появления в архиве. Исходная запись6819 подтверждена первым коммитом данных; фиктивные прошлые версии не добавляются. При новом сохранённом клиенте запись добавляется автоматически, одинаковый клиент не дублируется. Локальный API `/api/version-history` читает историю с диска без перезапуска; Pages использует опубликованный JSON.

Сначала можно проверить кандидат из терминала:

```sh
npm run data:update -- --dry-run
npm run data:update
npm run knowledge:import
```

CLI сохраняет локальные данные. Публикация запускается кнопкой локального центра либо вручную в [GitHub Actions](https://github.com/Roman17-bot/deadlock-archive/actions/workflows/refresh-data.yml): **Run workflow → Run workflow**. Workflow повторно проверяет источники, выполняет тесты/сборку, сохраняет только JSON/портреты и сам публикует Pages. Запуск в очереди ещё не означает успешное развёртывание; результат виден по ссылке задачи. Не нужен постоянно работающий ПК для Actions.

Если данные уже сохранены, но dispatch не удался, повторное обновление той же версии не отправляет публикацию: для восстановления используется ручной запуск Actions. Ошибка сохранения истории не откатывает исправный снимок, но блокирует отправку публикации; сначала нужно восстановить корректный файл истории и проверить `npm run data:check`.

На публичном сайте **«Проверить обновления»** загружает уже опубликованный снимок и сравнивает его с доступной версией API. Если новая версия ещё не опубликована, это показано явно. Для записи на ПК/в репозиторий используются локальный центр владельца или авторизованный Actions, а не секрет в публичном JavaScript.

Источники — поддерживаемые сторонние извлечения файлов Valve, без обещания мгновенного официального API или отсутствия закрытых server-side hotfix. Если схема/особая механика неизвестна либо версии расходятся, обновление останавливается с сохранением последнего рабочего снимка. Backups: `work/backups/updates/`. Обычный сбой сохранения откатывается; единая транзакция двух JSON при отключении питания не обещается. Автообновление героев не пересматривает формулы: для нового клиента механики помечаются требующими сверки.

## База знаний и навык

```sh
npm run knowledge:import
npm run knowledge -- status
npm run knowledge -- search "вампиризм" --limit 5
npm run knowledge -- formula lifesteal-amp
npm run skill:install
```

База `knowledge/archive.sqlite` остаётся приватной. История и источники сохраняются; raw способности/предметы считаются текущими только для совпадающей версии героев. Если нового raw cache нет, статус это показывает, старые записи доступны через `--history`. Навык устанавливается в пользовательскую папку Codex; подробнее [docs/knowledge.md](docs/knowledge.md).

## Публикация

GitHub Actions проверяет данные, тестирует и собирает сайт на Node24, затем публикует dist в GitHub Pages. VITE_BASE_PATH задаётся как /имя-репозитория/. Hash-маршруты #/, #/heroes, #/mechanics и #/updates работают без серверных перенаправлений. Статические данные и ресурсы используют тот же base path.

GitHub Pages не запускает Node.js: публичная версия работает с JSON. API остаётся готовым для будущего размещения на Node-сервере. Полные личные исследования, исторические журналы матчей и рабочие файлы хранятся в ignored knowledge/, outputs/ и work/, не загружаются в публичный репозиторий.
