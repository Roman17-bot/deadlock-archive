# Deadlock Archive

Независимый справочник Deadlock: главная, реестр героев, механики с калькуляторами и центр обновлений. Число героев, версия клиента и даты обновления берутся из сохранённых данных.

## Что работает

- Поиск по английским именам и русским вариантам.
- Сортировка каждого числового столбца в обе стороны.
- Уровни1–36 с индивидуальными приростами и встроенными Spirit-скейлами.
- Урон выстрела, расчётный DPS, HP, Spirit, регенерация и приросты за уровень.
- Примечания к особому оружию, источники и методика, CSV текущего результата.
- Подробности героя с понятными пояснениями урона, очередей, дробин, DPS и прироста от уровня/Spirit; исходные параметры раскрываются отдельно.
- Крупные шрифты и элементы управления; полная таблица прокручивается вместе со страницей.
- На узких экранах столбцы прокручиваются горизонтально, имя героя закреплено.
- На телефонах компактные режимы «Характеристики» и «Приросты за LVL»; примечания открываются нажатием на героя. CSV сохраняет все показатели выбранных героев.
- Справочник из27 правил с43 источниками и15 режимами калькулятора: EHP, урон, лечение, вампиризм, длительность, CDR, дальность, HP и другие.
- Владелец обновляет локальные данные и отправляет публикацию одной кнопкой. Источники проверяются по версии и raw-файлам; ошибочный кандидат не заменяет рабочие данные.
- Приватный SQLite/FTS5 индекс исследований и устанавливаемый навык для восстановления контекста проекта.
- Переиспользуемые роли агентов, отдельная частная память и экономные параметры вызовов: [команда проекта](docs/agents.md).
- Локальная PostgreSQL: герои, оружие, механики RU/EN, источники и история снимков; миграции, резервные копии и проверяемый экспорт.
- RU/EN на всех страницах, включая заметки, формулы, калькуляторы и скачиваемый разбор. Язык сохраняется в браузере; форматы дат/чисел и заголовки CSV следуют выбранному языку.

## Локальный запуск

Нужны **.NET SDK 10**, **Node.js 24.15+** и npm. Для режима БД — локальный PostgreSQL 18 и его клиентские утилиты.

```sh
npm ci
npm run dev
```

`npm run dev` запускает Vite и ASP.NET Core API вместе, ждёт готовности обоих и автоматически открывает главную страницу в новой вкладке **Google Chrome**. `Ctrl+C` останавливает оба сервиса. После первого `npm ci` для ежедневного запуска нужна только эта одна команда.

Сайт: http://127.0.0.1:5173/ . ASP.NET Core API: http://127.0.0.1:3001/api/heroes . Проверка API: /api/health . Сервер слушает только loopback. Локальная разработка читает живой API через Vite proxy; GitHub Pages читает статический снимок. После обновления локальный API использует новые данные без перезапуска.

После запуска API сначала отдаёт сохранённые данные, затем в фоне проверяет обновления и официальные описания патчей. При настроенной БД изменения по умолчанию публикуются. `DEADLOCK_AUTO_UPDATE=0` отключает стартовую проверку; `DEADLOCK_AUTO_PUBLISH=0` отключает её автоматическую публикацию.

При настроенном `.env.local` API читает PostgreSQL. Первый запуск заполняет только пустую БД; существующие записи не заменяются файлами при перезапуске. Ошибка подключения показывается явно. Без конфигурации БД проект работает с JSON, в том числе на GitHub Pages и в обычной CI-сборке.

```sh
npm run db:status
npm run db:backup
```

На новом компьютере с PostgreSQL сначала выполни `npm run db:setup`: пароль администратора вводится скрыто, для приложения создаётся отдельная роль и приватный конфигурационный файл. Подробные команды, схема и подключение VS Code — в [docs/database.md](docs/database.md).

```sh
npm run backend:build
npm run backend:test
npm test
npm run typecheck
npm run data:check
npm run build
npm run preview
```

Для отдельного запуска: npm run dev:web или npm run dev:api. Порт API меняется через API_PORT (прокси использует то же значение). Если Chrome установлен в другом месте, задай CHROME_PATH полным путём к исполняемому файлу. NO_OPEN=1 отключает только автооткрытие браузера, например на сервере разработки.

## Архитектура

```text
backend/Deadlock.Api/   ASP.NET Core 10: HTTP, CLI, EF Core 10/Npgsql, ingestion, sync
backend/Deadlock.Tests/ тесты native backend
data/                  проверенный публичный JSON
db/                    совместимые SQL-миграции и примеры запросов
shared/                типы, проверка данных и расчёты браузера
src/                   React: страницы, компоненты, сервисы и RU/EN
public/assets/         портреты, иконки предметов и шрифты
scripts/               тонкие CLI-запуски .NET, Vite и приватные SQLite-инструменты
tools/skills/          поддерживаемые навыки проекта
tests/                 тесты браузерной логики и сценариев
```

Публичные изменения проходят через проверенный пакет `data/`; `public/data/` генерируется перед запуском и сборкой. Локальное рабочее хранилище — PostgreSQL. Импорт сохраняет полный снимок одной транзакцией и переключает текущую версию только после успеха. `db:export` создаёт отдельную папку для проверки, без публикации и перезаписи `data/`. Типы — в `shared/`, расчёты — в `shared/heroes.ts` и `shared/mechanics.ts`. Значения сохраняются с исходной точностью, округляется только вывод.

У каждой страницы свой входной TSX-файл, CSS и связанные только с ней компоненты, хуки и модели. Например, таблица героев находится в `src/pages/HeroesPage/`, а её поиск, сортировка и CSV — в `hooks/useHeroRegister.ts`. Переиспользуемый калькулятор находится отдельно от страницы справочника. Подробная карта и правила добавления кода — в [docs/frontend-architecture.md](docs/frontend-architecture.md).

## Значение характеристик

LVL1 соответствует0Boons, каждый следующий уровень — ещё1Boon; максимум36/35. Spirit растёт индивидуально. Victor получает регенерацию через Spirit, Vindicta/GreyTalon/Solomon — дополнительный урон оружия. Warden имеет два представления одного скейла скорострельности, которые не складываются дважды.

Урон выстрела суммирует обычные попавшие дробины. Для hit-once несколько траекторий дают один урон по цели: Baba8,8 и Drifter19,5 на LVL1; прежнее умножение на3 исправлено. У очередей показан отдельный выстрел. Расчётный DPS исключает перезарядку, сопротивления, дистанцию, хедшоты, предметы и активные эффекты. Интервал сравнительной модели: cycle + (burst−1)×intraBurst; другие трактовки burst описаны в механиках. Движок не измерялся. У раскручивающегося оружия показан стартовый DPS.

Исторические источники расчётной модели клиента 6819 (не указание текущей версии): [версия клиента](https://api.deadlock-api.com/v1/assets/steam-info), [герои6819](https://api.deadlock-api.com/v1/assets/heroes?client_version=6819), [оружие6819](https://api.deadlock-api.com/v1/assets/items?client_version=6819), [фиксированная ревизия игры](https://github.com/SteamTracking/GameTracking-Deadlock/tree/17462b250a0ca80e7f80102f2c83cc3eecff5f12).

## Обновление данных и синхронизация

В локальном сайте открой `#/updates`. «Обновить данные» проверяет клиента и готовит героев, предметы и статистику вместе. При совпадении клиента игровые assets не перезагружаются. Независимая проверка официальной истории может сохранить новые описания патчей даже для того же клиента. При включённой публикации изменившийся пакет передаётся синхронизации.

«Синхронизировать с Pages» сравнивает содержимое PostgreSQL с файлами, GitHub и Pages: публичный JSON, портреты, иконки и манифест SHA256. Операция нужна и для правок внутри одной версии клиента. Сборка использует сохранённые данные без нового получения игровых assets; успешная публикация подтверждается проверкой файлов на Pages.

```sh
npm run data:update -- --dry-run
npm run data:update
npm run db:sync -- --dry-run
npm run db:sync -- --wait
```

`data:update` сохраняет локальные данные; явный `--publish` включает публикацию из CLI. `db:sync` публикует текущую БД. Dry-run не меняет публичные данные, БД или GitHub; подготовка обновления может оставить приватный кандидат и кеш истории в `work/`. `--wait` ждёт подтверждения Pages до десяти минут. Сохранение файлов, импорт БД, приватная индексация, коммит и развёртывание учитываются отдельно. Повтор публикации сверяет сохранённую задачу, а более новая версия на GitHub не перезаписывается автоматически.

История `versions` хранит реальные версии клиента и происхождение сборок. `history.patches` отдельно хранит официальные Steam-описания по news GID, с заголовком, текстом и датой. GID, Steam Build ID и номер клиента — разные идентификаторы; ближайшая дата не создаёт связь между ними. Фоновая загрузка сохраняет успешные страницы и продолжает незавершённую историю при следующей проверке. Формулы сохраняют свою дату и версию сверки.

Подробнее: [native backend](docs/backend.md), [PostgreSQL и публикация](docs/database.md), [предметы](docs/items.md). Сайт и команды не запускают игру.

## База знаний и навык

```sh
npm run knowledge:import
npm run knowledge -- status
npm run knowledge -- search "вампиризм" --limit 5
npm run knowledge -- formula lifesteal-amp
npm run skill:install
```

База `knowledge/archive.sqlite` остаётся приватной. История и источники сохраняются; raw способности/предметы считаются текущими только для совпадающей версии героев. Если нового raw cache нет, статус это показывает, старые записи доступны через `--history`. Навык устанавливается в пользовательскую папку Codex; подробнее [docs/knowledge.md](docs/knowledge.md).

Для текущих данных сайта доступны короткие запросы PostgreSQL: `npm run db:query -- hero "Nurse Harrow"` и `npm run db:query -- formula resistance ru`. Исследования и решения по проекту извлекаются из отдельного SQLite-архива. Для расчётов используется тот же проверенный модуль `shared/mechanics.ts`, что и в калькуляторе сайта.

## Публикация

GitHub Actions использует .NET для backend-команд и Node 24 для сборки Vite; GitHub Pages раздаёт готовый `dist`. VITE_BASE_PATH задаётся как /имя-репозитория/. Hash-маршруты #/, #/heroes, #/mechanics и #/updates работают без серверных перенаправлений. Статические данные и ресурсы используют тот же base path.

GitHub Pages раздаёт статические JSON и ресурсы. Локальный API выполняется в .NET и не размещается на Pages. Node нужен Vite, npm-запускам и приватному SQLite/FTS5-инструментарию; отдельного Node-сервера API нет. Полные личные исследования, исторические журналы матчей и рабочие файлы хранятся в ignored knowledge/, outputs/ и work/, не загружаются в публичный репозиторий.
