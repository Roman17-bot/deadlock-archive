# План: понятные подробности и история патчей

Спецификация: docs/superpowers/specs/2026-10-26-readable-details-patch-history-design.md. Основа:b8ca9e9; ветка codex/hero-details-patch-notes в существующем управляемом checkout. Оригинальная приватная база знаний остаётся в основном каталоге.

1. Пояснения героев (отдельный агент): HeroNotesRow, связанные модели/компоненты/CSS в HeroesPage; en-heroes.ts; тесты пользовательских сценариев. Числа/JSON/общая математика неизменны. Root подключает словарь и проверяет интеграцию.
2. Источники патчноутов (агент, только чтение): точные ссылки и соответствие clientVersion ↔ Steam build, ограничения обновления. Без обхода403 и привязок только по дате.
3. История (root): optional typed patch metadata в shared/version-history.ts с URL/размерной валидацией; история обновлений сохраняет точный источник для новых клиентов; миграция002 + repository round-trip; интерфейс VersionHistory и RU/EN. Новые проверки сначала показывают отсутствие функции, затем становятся зелёными.
4. Внедрение: ограниченная проверка актуального содержимого БД, backup, согласование нового публичного пакета с БД без потери пользовательских записей, нормальная публикация снимка. Игру не запускать, same-client обновление не менять.
5. Интеграция/QA/review: все тесты и типы, проверка данных/экспорта/сборки, desktop/mobile/RU/EN, независимый обзор; коммит/main/CI/Pages, точное совпадение опубликованного JSON с БД и запись решения в приватном архиве.

Риски: дробины и очереди не должны считаться одним нажатием; Spirit-рост нельзя учитывать дважды; старый патч не должен терять метаданные при экспорте; неверная или опасная URL блокируется; отсутствие патчноута/поздняя новость не превращается в выдуманное описание; сбой источника не мешает проверенному игровому снимку; содержимое HTML не исполняется; отсутствие сохранения истории или БД блокирует публикацию.
