# Формулы, обновление данных и память проекта

Дата: 25 октября 2026. Пользователь передал решения исполнителю; отдельное согласование дизайна не требуется.

## Назначение и порядок

1. Сначала исследовать формулы и записать русский справочник с источниками, примерами и исключениями.
2. Затем реализовать страницу «Механики» и интерактивные калькуляторы.
3. Добавить проверяемое обновление героев/версии и публикацию без участия ассистента.
4. Создать локальную SQLite базу знаний и устанавливаемый навык восстановления контекста.

Уточнение пользователя: согласующиеся независимые наблюдения нескольких авторов достаточны для рабочей формулы. Такие правила применяются и в калькуляторах; их происхождение остаётся видимым. Полная закрытая реализация движка недоступна, поэтому наблюдения сообщества не переименовываются в доказательство из исходного кода.

## Решения

Сохраняем React/TSX/Vite, Node.js 24 и обычный CSS, существующую нуарную палитру и мобильную таблицу. Работа в текущей папке на отдельной ветке codex/mechanics-and-data-update; новый checkout не нужен. Игра не запускается.

### Исследование

Проверяем локальную steam.inf, свежий steam-info API, неизменяемый commit GameTracking и первичные конфиги. Для правил, отсутствующих в открытой реализации, сравниваем независимые эксперименты/объяснения. Каждая формула имеет id, тему, запись, переменные, русский разбор, числовой пример, ограничения, evidence, checkedAt и reviewedClientVersion. Ссылки на текущие численные параметры закрепляются на commit. Категории доказательств: математическое тождество; параметры из файлов игры; согласованное описание сообщества; спорная модель. При новой версии игры помечаем, что механические правила требуют повторной сверки. Автообновление героев не означает автоматической проверки всех механик.

### Страница

Маршрут #/mechanics. Навигация по темам, поиск в формулах, заметные статусы источников, разворачиваемые пояснения. Сначала область калькуляторов с выбором задачи, затем полный справочник. На мобильном всё располагается одной колонкой без горизонтального прокручивания страницы. Числа допускают десятичную запятую; пустое/невалидное поле не становится молча нулём. Ошибки и недопустимое 100% сопротивление объясняются возле результата. Округляем только вывод.

Планируемые задачи: сопротивления и эффективное здоровье; урон и усиление; лечение/вампиризм; длительность дебаффа и замедление; перезарядка способности; приросты/Spirit; длительность и радиус. Итоговый набор уточняется по результатам пункта 1. У каждого калькулятора есть ссылка на правила и ограничения. HP и EHP показаны отдельно; отдельные типы сопротивлений не смешиваются.

### Обновление

Рассмотрены: прямой fetch API в браузере; локальный Node updater; GitHub Actions. Прямой fetch не сохраняет данные для друзей и не может безопасно владеть GitHub секретом. Выбран общий проверяемый pipeline, который работает в Node локально и в Actions.

Источник чисел: текстовые файлы текущей версии клиента из GameTracking, сверенные по версии/ревизии с Deadlock API. API даёт имена, иконки и удобную вторую сверку. Это извлечение файлов Valve сторонними поддерживаемыми сервисами, а не обещание официального полного публичного API Valve.

Snapshot собирается в памяти, проверяется на схему, уникальность, версию, границы чисел и поддержку модели. Неизвестные поля, изменяющие расчёт, останавливают замену с объяснением. Перед сохранением создаётся резервная копия; canonical JSON заменяется атомарно. Портреты новых героев добавляются вместе с данными. Обновлённый локальный API читает новый снимок без перезапуска. На сайте версия, количество героев и даты берутся из metadata, а не из строк, зашитых в JSX.

Локальная кнопка инициирует задачу сохранения и, по умолчанию, авторизованный workflow_dispatch публикации. GitHub credential остаётся в серверном процессе, берётся из существующего credential manager и не отправляется в браузер/логи. Endpoint привязан к loopback, проверяет Host, точный локальный Origin, nonce и JSON тип. Одновременно работает только одна задача. Публичная страница даёт ссылку открыть локальный центр в новой вкладке либо авторизованно запустить Actions в GitHub; гостям доступна загрузка уже опубликованного снимка и проверка версии. CORS-доступ к изменяющим локальные файлы endpoint с публичного сайта не открывается: это избегает общего Origin всех Pages одного аккаунта и браузерного разрешения Local Network Access. Отсутствие локального сервера не выдаётся за успешное сохранение.

Workflow обновления запускается только вручную, использует ограниченные permissions, проверяет данные/тесты/сборку, сохраняет только предусмотренные файлы и сам публикует Pages после своего commit. Это учитывает, что push с GITHUB_TOKEN не запускает обычный push workflow. Публикация отслеживается отдельно от локального сохранения; ошибка публикации не уничтожает локальный снимок.

### Память

SQLite локально в knowledge/archive.sqlite, без сервера БД и без публикации частной базы. Версионируемые скрипты пересоздают индекс из JSON и локальных отчётов. Нормализованные таблицы: snapshots, entities, formulas, evidence, documents, decisions, update_runs; полнотекстовый поиск FTS5. Новые snapshots сохраняются исторически, а не перезаписывают все старые записи. CLI предоставляет status/search/entity/formula/import/decision и возвращает компактный JSON с происхождением и датой. Запросы параметризованы, результат ограничен, ключи и токены в базу не попадают. Документы сохраняют хеш и относительный путь.

Навык deadlock-project устанавливается в пользовательскую папку навыков, исходник хранится в репозитории. Короткий вход маршрутизирует к базе и конкретным справочникам, объясняет проверку свежести, ограничения утверждений, приоритет Nurse Harrow только в билдах/реплеях, запрет запуска игры без нового разрешения и разумное разделение исследовательских задач между агентами. Навык не загружает всю базу в каждый контекст. Отдельный AGENTS.md проекта помогает обнаружению и хранит стабильные команды, не дублирует весь справочник.

## Проверка

Математика: независимо посчитанные примеры, границы, отрицательное сопротивление, смешанный урон и невалидные числа. UI: работа калькуляторов, режимов, поиска, доступных подписей, обновления и отказа сети. Pipeline: фикстуры current6819, смена версии в середине чтения, неверная схема/числа, неизвестные модификаторы, резервная копия и неизменность canonical при ошибке. Сервер: блокировка постороннего Origin/Host и неверного nonce, конкуренция задач, частичный сбой публикации. SQLite: реальная временная БД, повторный импорт, FTS русский/английский, сохранение истории и источников. Навык: независимый практический retrieval-тест.

Перед выпуском: полные тесты, typecheck, data validation, Pages build; свежая независимая проверка; реальный мобильный и настольный браузер; успешный deploy и проверка публичного сайта.
