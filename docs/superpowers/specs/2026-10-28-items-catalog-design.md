# Каталог предметов

Создать раздел, в котором игрок может найти предметы под конкретную ситуацию, прочитать характеристики и сравнить реальные покупки. Дизайн и технические решения поручены пользователем координатору; дополнительное согласование не требуется.

## Представление

`#/items` показывает все доступные предметы обычного магазина: три колонки «Оружие», «Выживаемость», «Спирит», внутри каждой тиры 1–4. У каждого предмета иконка, название, цена, обозначение активного эффекта. Наведение мышью или фокус клавиатуры открывает карточку с параметрами и описанием. Нажатие ведёт на `#/items/<slug>`. На телефоне категории перестраиваются в читаемые секции, параметры доступны на странице предмета, фильтры — в раскрывающейся панели. Весь каталог прокручивается вместе со страницей.

Над каталогом: поиск по обоим языкам, категории, тиры, активные/пассивные. Панель игровых задач группирует защиту, противодействие, контроль, восстановление, мобильность, оружие и способности. Выбранные условия всегда видны, снимаются по отдельности; доступны очистка и режимы «все»/«любое». Пустой результат объясняет, как ослабить запрос. Число результатов у условий рассчитывается по текущему запросу. URL сохраняет фильтры для ссылки и возврата из предмета.

## Подробности предмета

Иконка, категория, тир, стоимость, активные/пассивные свойства, описание каждого эффекта и условия срабатывания. Компоненты и следующие улучшения — ссылки на предметы. Практические советы основаны на свойствах; не выдавать их за выводы просмотра записей. Статистика: доля побед после покупки, число покупок, среднее время покупки, герои с наибольшим числом покупок (отдельно винрейт и время). Период, обычный режим и охват рангов указаны рядом. Объяснить одной строкой, что доля побед после покупки не равна бонусу к шансу победы. Нет данных — явное пустое состояние, без выдуманных процентов.

## Данные и ограничения

Актуальный источник API на 28.10.2026 сообщает клиент 6821. 156 доступных предметов тиров1–4, ещё17 Legendary вне запрошенного магазина. Данные RU/EN берутся из версионированных assets API, цены/категории/свойства сохраняются. Описания преобразуются в обычный текст, SVG/HTML и внутренние идентификаторы не попадают в интерфейс. Фильтры учитывают сторону применения эффекта: отрицательное лечение владельца не становится антихилом противника; щит не становится сопротивлением; сокращение дебаффа не становится очищением.

Публичные `data/items.json` и `data/item-statistics.json` содержат только отобранные поля. Иконки хранятся локально в `public/assets/items/`. Источники/сырьё/расхождения сохраняются в приватном архиве. Статистика из documented item-stats API, с фиксированными from/to, normal, ranked/unranked, без corrupted. Начало периода не раньше выпуска текущей версии; отсутствие точного фильтра build не скрывать в приватном описании метода. Публичная дата периода достаточна.

PostgreSQL хранит предметы и статистику в версионируемых таблицах, экспорт восстанавливает те же JSON. Точная синхронизация охватывает оба JSON и иконки; проверка байтов, защита путей и ограничения размеров сохраняются. Старые архивы без предметов остаются читаемыми, новая функция вводится явным импортом, не перезаписью БД при старте. Обновление игры обновляет каталог до публикации; same-client no-op остаётся. Отдельная команда обновления предметов/статистики подходит для первоначального наполнения и свежей статистики внутри версии.

## Подходы

1. Запрашивать сторонний API из каждого браузера: данные свежие, но Pages зависит от доступности/CORS и все пользователи расходуют лимиты.
2. Сохранять единые данные в PostgreSQL и публикуемых JSON: одинаковые данные локально и на Pages, воспроизводимая статистика и существующая синхронизация. Выбрано координатором.
3. Собрать собственный парсер всех повторов: потребовал бы отдельного проекта и обработки большого массива матчей. В этом разделе используются готовые агрегаты; записи матчей не объявляются просмотренными.

Стек, нуарное оформление и существующие страницы сохраняются. RU/EN полностью поддерживается. Новые зависимости не требуются. Игру не запускать. Учетные данные в браузер не передавать.
