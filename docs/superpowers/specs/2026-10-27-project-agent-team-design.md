# Переиспользуемая команда Deadlock

Пользователь поручил создать специализации, отдельную память, навыки, экономный выбор моделей и независимого критика. Решения делегированы исполнителю.

Подход: семь именованных ролей (`heroes`, `items`, `mechanics`, `website`, `data`, `critic`, `scout`), проектные TOML-определения Codex и один компактный навык `deadlock-team` с отдельными инструкциями каждой роли. Один общий навык уменьшает дублирование и стоимость каталога. Память ролей — `knowledge/agents/<role>/CONTEXT.md` в исходном частном архиве; задания и отчёты получают отдельные каталоги. Время жизни процесса агента не считается постоянной памятью.

Специалисты по умолчанию используют GPT-6.1 Sol/medium; механики — high. Одноразовый scout — GPT-6 Luna/low. Для отдельной сложной проверки разрешено явное повышение уровня; GPT-6 Astra/high — только обоснованный аудит. Каждый вызов задаёт и модель, и reasoning; весь чат не копируется. Простой вопрос решается напрямую без команды. Параллельно до трёх дочерних агентов, обычно один-два. Критик получает артефакт/дифф и пользовательские требования, а не указание подтвердить вывод автора.

Координатор выдаёт границы чтения/записи и объединяет краткие отчёты. Только координатор обновляет общий контекст, индексирует принятые исследования и публикует. Ролевые контексты не дублируют сотни игровых чисел. Источники/версии/даты и статус проверки обязательны для игровых выводов; совпавшие зависимые сайты не считаются независимыми подтверждениями. Согласованная сообществом модель может использоваться в расчётах с указанием её статуса. Противоречия и ограничения сохраняются.

CLI `npm run team -- status|context ROLE|brief ROLE --task TEXT` возвращает ограниченный контекст или готовые аргументы spawn. `brief` ничего не запускает и не пишет. `team:init` создаёт недостающие каталоги без перезаписи памяти. `team:install` устанавливает только поддерживаемый навык. Существующий навык проекта и AGENTS.md маршрутизируют к команде. Пароли/конфиги/сырые исследования не публикуются; сайт, БД и формулы не меняются. Глобальная модель основного чата не меняется.

Проверка: тесты CLI, безопасных путей, моделей, установки и повторной инициализации; валидация TOML/навыка; baseline нового агента до навыка и реальные короткие задания с навыком. Не обещать проверенный автоматический подхват роли текущим инструментом, если у него нет `agent_type`: использовать готовые явные параметры spawn. Критик подключается по событию крупного этапа/спорного вывода или запросу пользователя, без фонового расписания.

Источники формата: [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents), [Configuration Reference](https://learn.chatgpt.com/docs/config-file/config-reference), [Skills](https://learn.chatgpt.com/docs/build-skills), проверены 27 октября 2026. Локальный CLI 0.133.0 использует совместимые привязки `agents.<role>.config_file`, а новые scalar-defaults агента не понимает; модели задаются в роли и явном вызове. Глобальное значение reasoning=max для этого CLI не поддерживается; диагностические чтения используют временный override medium без записи настроек.
