# Понятные подробности героев и патчноуты истории

Владелец просит заменить непонятный вывод технических примечаний объяснениями для игроков и открывать описание конкретного патча по версии в истории. Ранее он поручил самостоятельно принимать решения по развитию сайта; дополнительных согласований не требуется.

Подробности героя сохраняют проверенные числа и расчёты. Основной блок показывает короткие подписи, особенности оружия, смысл DPS и прироста от уровня/духовной силы. Технические названия и исходные примечания доступны в закрытом details с источниками. Для обычного дробовика, очереди, разового урона по цели, луча и раскрутки объяснения различаются. Выбранный уровень, RU/EN, сортировка, CSV и мобильная таблица продолжают работать.

Запись истории получает необязательные проверяемые сведения о публикации изменений: вид (описание патча или изменения файлов), источник, ссылка, при необходимости заголовок и короткое описание RU/EN. Версия становится ссылкой в новой вкладке; рядом видны тип и источник. Отсутствие официального описания обозначается явно. HTML сторонних публикаций не встраивается. Старые записи без этих полей остаются валидны. Данные проходят JSON → PostgreSQL → экспорт → публичный снимок без потерь; миграция добавляет nullable JSONB-поле и не переписывает прошлые снимки.

Точное соответствие важнее похожей даты: клиент6819 не является номером Steam-сборки. Для текущего клиента сверена сборка26147187; SteamDB сообщает отсутствие официального патчноута. Хранятся ссылка именно на эту сборку и честное описание результата проверки. Для новых сохранений доступна точная ссылка на ревизию GameTracking; надёжные сведения Steam/Valve могут дополнять её. Соседняя по дате новость не выдаётся за описание другого хотфикса. Доступность необязательного источника не блокирует сохранение проверенных данных игры, не меняет same-client no-op и не запускает отдельную публикацию при проверке.

Выбран подход с внешними первоисточниками и публичными метаданными: он сохраняет полные оригинальные патчноуты и не требует HTML-скрапинга SteamDB, который возвращает403. Копирование целых статей и автоматическая привязка только по дню отклонены из-за лишнего объёма и неоднозначности нескольких сборок за день. Поддерживаемые источники точной автоматической привязки исследуются отдельно.

Исследование подтвердило готовый источник: сообщение pinned-коммита GameTracking начинается номером клиента и содержит URL SteamDB с Build ID. При обычном обновлении используется уже полученный объект коммита, без дополнительного скрапинга или запроса. Несовпадающий номер клиента, неоднозначные ID и неверные адреса дают ссылку на точный коммит файлов. Автоматическая запись не утверждает наличие официальных заметок; это показывает страница источника. Для текущей сборки отсутствие заметок проверено отдельно и сохранено как `unpublished`.

Проверка: пользовательские сценарии пояснений/уровней/особого оружия и RU/EN; безопасные ссылки/невалидные метаданные и старые записи; round-trip PostgreSQL; сохранение истории и same-client no-op; мобильные снимки; полный набор тестов, build и фактический Pages. Перед рабочей миграцией и импортом — резервная копия. Изменения содержимого публикуются через проверенный снимок БД; код и данные согласуются без перезаписи чужих изменений.
