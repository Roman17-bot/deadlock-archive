# Тексты сайта

Пишем для игроков: называем характеристику, объясняем действие и показываем пример. Русская и английская версии должны передавать один смысл.

- В интерфейсе используем «версия», «данные», «обновлено». Технические слова вроде «снимок», «срез», raw и имена полей остаются в документации разработчика.
- Не добавляем к каждому правилу историю проверки, оценку уверенности и список источников. Происхождение данных, расхождения и исследовательские заметки сохраняем во внутреннем архиве.
- Условия расчёта оставляем там, где они влияют на результат: например, DPS без перезарядки, постоянное сопротивление, один тип урона. Объясняем их коротко, без оправданий.
- Не превращаем редактуру в новое исследование: не меняем числа и формулы и не приписываем им проверку, которой не было.
- В подробностях героя объясняем поведение оружия обычными словами. Классы оружия, флаги, пути файлов и внутренние названия не выводим.
- Ссылки на SteamDB и изменения игры оставляем в истории версий. Служебные ссылки на публикацию нужны только рядом с соответствующей операцией.
- Убираем повторы, общие обещания и фразы, которые ничего не добавляют. Предпочитаем «Выбери уровень, чтобы сравнить характеристики» формулировке «Сначала факты, затем эксперименты» в поясняющем тексте. Оформление заголовков может сохранять нуарный стиль сайта.
- Проверяем не только основной текст, но и подсказки, раскрывающиеся блоки, ошибки, загрузку, переводы и скачиваемый справочник.

В качестве редакторского справочника изучен [Humanizer](https://github.com/blader/humanizer/blob/main/SKILL.md). Используем его рекомендации по ясности и повторам; автоматическую оценку «нейронности» не считаем показателем качества текста. Удалённый код и зависимости для этого не устанавливались.
