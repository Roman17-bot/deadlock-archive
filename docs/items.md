# Предметы

`#/items` показывает обычный магазин: оружие, выживаемость и спирит, тиры 1–4. Поиск предметов учитывает оба языка, описания и названия свойств. Тиры оформлены отдельными кнопками с ценами из каталога; активные и пассивные предметы выбираются в соседнем блоке. Кнопка сброса всегда доступна и очищает все условия и оба поисковых поля.

Разделы магазина переключаются между «Все категории» и одним из трёх разделов. «Предметы под ситуацию» содержит кнопки всех свойств по группам: защита, противодействие, контроль, лечение, передвижение, оружие и способности. Можно выбрать одно свойство или «Все свойства»; новый выбор заменяет предыдущий. Число на кнопке показывает количество предметов после такого переключения с учётом остальных фильтров. Поиск свойств находит кнопки и раскрывает совпадения, не меняя саму выдачу.

На широком экране панель находится слева от поиска и каталога. Каталог использует до 2048 px, панель — 320–360 px в зависимости от ширины окна. При выборе одного раздела карточки заполняют доступную ширину. Страница отдельного предмета сохраняет прежнюю ширину.

Условия предметов сохраняются в ссылке; возврат со страницы предмета восстанавливает запрос. Поисковая строка для поиска переключателей — временная настройка интерфейса и в ссылку не попадает.

Старые ссылки с несколькими разделами или свойствами используют первый допустимый вариант; режим all/any больше не используется в интерфейсе. Новые ссылки содержат не более одного раздела и одного свойства.

На компьютере краткое описание открывается наведением или фокусом клавиатуры, Escape его закрывает. Нажатие открывает `#/items/<slug>` с параметрами, эффектами, советами, компонентами, улучшениями и статистикой. На телефоне свойства находятся в раскрывающихся группах; поиск свойств доступен сразу. Карточка открывается нажатием.

## Код и данные

- `shared/item-types.ts` — общий контракт; `shared/items.ts` — проверка входных данных.
- `shared/item-filters.ts` — группы свойств и сопоставление запроса.
- `server/items/normalize.ts` — отбор обычных продаваемых предметов, RU/EN, безопасный текст вместо HTML/SVG.
- `server/items/traits.ts` — свойства с учётом цели применения, условия и советы.
- `server/items/source.ts` — ограниченные запросы версионированных assets, статистики и WebP-иконок.
- `server/items/archive-refresh.ts` — подготовка полной версии в отдельной папке и согласованное сохранение.
- `data/items.json`, `data/item-statistics.json`, `public/assets/items/` — публичные файлы. Сырые ответы и исследовательские заметки приватны.

Статистика — агрегаты Deadlock API `item-stats`, отдельно общие и по герою. Запросы задают одинаковый период, normal, ranked/unranked и corrupted=exclude. Начало периода не раньше выпуска клиента; максимум последние14дней. API не фильтрует по номеру клиента: номер связывает каталог и период. `wins/matches` — доля побед в наблюдениях с покупкой, не изменение шанса победы. Подписываем число «покупок», не «уникальных матчей». `avg_buy_time_s` — среднее фактическое время, не рекомендация оптимального момента. Герои сортируются по числу покупок, не по доле покупок внутри героя.

## Обновление

Перед первым изменением рабочей базы: `npm run db:backup`. Проверка предметов: `npm run items:refresh -- --dry-run`; сохранение: `npm run items:refresh`.

При настроенном PostgreSQL команда берёт остальные данные из БД, сохраняет предметы в JSON и транзакционно импортирует полную версию. `localSaved` и `databaseSaved` сообщают об этапах отдельно. Публикация этой командой не запускается. Dry-run не меняет публичные файлы и БД.

Публикация: «Синхронизировать с Pages» или `npm run db:sync -- --wait`. Проверка без записи: `npm run db:sync -- --dry-run`. Сравнение включает оба JSON, иконки и остальные данные сайта.

Обновление игры готовит героев и предметы вместе. При ошибке загрузки сохраняется прежняя версия и можно повторить попытку. Совпадение версии игры остаётся no-op; свежая статистика внутри той же версии обновляется отдельной командой предметов.
