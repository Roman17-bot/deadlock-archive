# Команда специалистов Deadlock

Роль сохраняется в инструкциях и файлах, а не в постоянно запущенной модели. В пределах чата координатор может повторно вызвать подходящего агента; в новом чате или после выгрузки процесса новый исполнитель восстанавливает ту же специализацию из её папки. Агент не считается «помнящим всё» только из-за имени.

| Роль           | Область                                                          | Модель и размышление по умолчанию |
| -------------- | ---------------------------------------------------------------- | --------------------------------- |
| `heroes`       | Умения, характеристики, билды, матчапы, синергии, реплеи         | GPT-6.1 Sol / medium              |
| `items`        | Предметы, порядок покупок, ситуативность, взаимодействия         | GPT-6.1 Sol / medium              |
| `mechanics`    | Формулы, порядок эффектов, вычисления и спорные модели           | GPT-6.1 Sol / high                |
| `website`      | React, Node.js API, интерфейс, доступность и визуальная проверка | GPT-6.1 Sol / medium              |
| `data`         | PostgreSQL, источники, обновление патча и синхронизация Pages    | GPT-6.1 Sol / medium              |
| `critic`       | Независимая проверка выводов, результата и направления проекта   | GPT-6.1 Sol / medium              |
| `scout`        | Один поиск, небольшой лог, адресная проверка                     | GPT-6 Luna / low                  |
| `designer`     | Визуальный стиль, графика, иконки, кастомные анимации и макеты   | GPT-6.1 Sol / medium              |
| `designcritic` | Независимая проверка дизайна, анимаций, удобства и доступности   | GPT-6.1 Sol / medium              |

Модели/уровни заданы в `tools/agents/roles.json`. `quick` — Luna/low; `standard` — Sol/medium; `deep` — Sol/high. Дорогой `audit` — Astra/high, только для критика или механик и с записанной причиной. Это выбор параметров и ограничение объёма задания, а не обещание фиксированного количества токенов. Доступность моделей каждый раз сверяется с реальными инструментами клиента.

## Память и обязанности

```text
tools/agents/roles.json                       реестр и параметры вызова
.codex/config.toml                           лимит и привязки дочерних ролей
.codex/agents/deadlock-*.toml                 проектные определения ролей
tools/skills/deadlock-team/                   общий навык и отдельные инструкции ролей
knowledge/agents/<role>/CONTEXT.md            короткая частная память роли
knowledge/agents/<role>/runs/<id>/            отдельное задание и его отчёт
knowledge/archive.sqlite                     общий индекс доказательств
```

`knowledge/` существует только в исходном локальном репозитории и исключён из Git/Pages. Worktree использует локатор установленного `deadlock-project`, поэтому не создаёт параллельную неполную базу. PostgreSQL остаётся источником текущих локальных данных сайта; SQLite хранит доказательства и историю. Эти базы не заменяются ролевыми заметками.

Исполнитель получает конкретный вопрос, адреса нужных источников, разрешённые файлы для изменения и отдельный каталог отчёта. Память читается ограниченно: до6000 символов, затем адресно нужный документ. Длинные отчёты не копируются в главный чат. Ролевые каталоги задают порядок работы, но не создают отдельную системную песочницу.

`designer` создаёт концепции, графику, иконки и рабочие прототипы анимаций в своём частном каталоге задания. Для движения передаёт CSS/SVG/React или Web Animations API, условия запуска, тайминги, прерывание и reduced motion. `designcritic` независимо проверяет конкретный макет или реализацию: визуальную иерархию, понятность действий, доступность, RU/EN, узкие экраны и поведение анимаций. Обе роли по умолчанию используют Sol/medium и возвращают до450 слов; они не получают права менять код сайта. Готовые ресурсы и код интегрирует координатор или `website`. Общий `critic` сохраняет проверку доказательств, корректности и направления проекта.

Только координатор объединяет принятые выводы в `CONTEXT.md`, переносит полезные исследования в датированные `knowledge/research/` и индексирует их. Черновики `knowledge/agents/` автоматически не индексируются. Это сохраняет различие между гипотезой и принятой моделью и исключает одновременную перезапись общей памяти разными исполнителями.

## Команды

```powershell
npm run team:init
npm run team -- status
npm run team -- context heroes
npm run team -- brief scout --task "Найди файл, отвечающий за мобильную таблицу"
npm run team -- brief website --task "Исправь подтверждённый дефект таблицы" --write src/pages/HeroesPage/HeroesPage.css
npm run team -- brief mechanics --task "Сравни две модели расчёта вампиризма"
npm run team -- brief designer --task "Подготовь макет каталога и передачу реализации"
npm run team -- brief designcritic --task "Независимо проверь макет каталога и мобильный сценарий"
npm run team -- brief critic --depth audit --reason "Независимые источники противоречат друг другу" --task "Проверь вывод о порядке эффектов"
npm run team:install
npm run design:install
npm run skill:install
```

`brief` возвращает JSON с полем `spawn`: имя задачи, модель, reasoning, `fork_turns: none` и готовое задание. Команда **ничего не запускает, не публикует и не записывает**. Координатор передаёт именно объект `spawn` доступному инструменту субагентов. Идентификаторы старых процессов не хранятся как постоянные адреса ролей: сначала проверяется живой исполнитель, затем используется повторный вызов или новый процесс.

`team:init` создаёт недостающие папки контекста для всех ролей реестра; повторный запуск сохраняет существующую память. Если исходный архив не найден, можно явно указать `--archive-root "ПУТЬ_К_ИСХОДНОМУ_РЕПОЗИТОРИЮ"`. Новый индекс самопроизвольно не создаётся. `team:install` копирует только поддерживаемый навык, включая инструкции всех зарегистрированных ролей, и пишет частный локатор; посторонние навыки не удаляются. После переноса репозитория нужно переустановить навыки.

## Навыки дизайна

Рамки работы заданы в [визуальном направлении](design-brief.md). `deadlock-design` содержит правила графики, иконок и рабочих анимаций; `deadlock-design-review` — независимую проверку результата. Их поддерживаемые исходники находятся в `tools/skills/`; `npm run design:install` устанавливает оба навыка и частный локатор исходного архива, не меняя посторонние навыки. После установки обнаружение навыков обновляется в следующем ходе клиента; текущий исполнитель может читать их файлы напрямую.

Установлены два внешних навыка: [Frontend Design от Anthropic](https://github.com/anthropics/skills/tree/main/skills/frontend-design) для выразительного оформления и [Web Design Guidelines от Vercel](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines) для проверки интерфейса. Проверенные версии от 29 октября 2026: `ca45fc496a3436251f191354091d557da31c15b5` и `1a2c79d4e6c4a2283dc2c614b6538cbe1ed5ca62` соответственно. Установка выполнена официальным `skill-installer`; проектная команда `design:install` не скачивает и не обновляет внешние пакеты. Правила Vercel получают заново перед соответствующей проверкой кода. Внешние рекомендации не отменяют выбранный пользователем нуар и сохранение расположения элементов.

Дизайнер передаёт конкретные файлы; критик проверяет их независимо; `website` внедряет принятый вариант; затем сравниваются фактические экраны. Для простого визуального изменения вызываются только нужные роли. Само наличие этих инструкций не означает, что редизайн сайта уже выполнен, и не запускает агентов в фоне.

`npm run team -- configure` воспроизводит проектный конфиг и по одному TOML-файлу на роль из реестра. Существующий конфиг без пометки владения команды не перезаписывается. Он не изменяет глобальные настройки, разрешения или основную модель чата. Реестр проверяет уникальные безопасные имена, параметры модели и размышления, положительные ограничения объёма и числа исполнителей, не фиксируя число ролей.

## Когда подключается критик

Крупный законченный этап, спорная формула/билд, существенное изменение нескольких подсистем или запрос пользователя. Проверка ограничена конкретным результатом: нет обязанности заново исследовать всю игру при маленьком CSS-исправлении. Обычно достаточно одного независимого просмотра и проверки исправлений.

Критик проверяет источники и даты, реальные действия и тесты, альтернативные модели, соответствие исходному запросу, приватность и лишние расходы. Он возвращает до пяти подтверждаемых замечаний с важностью и доказательствами либо «существенных замечаний нет». Другая модель не гарантирует отсутствие ошибки; итоговые важные выводы проверяет координатор. Совпадающие сайты, которые копируют один источник, не становятся независимыми доказательствами. Согласованную сообществом формулу можно использовать как рабочую модель с её условиями и уровнем подтверждения.

Критик вызывается по событию, а не по фоновому расписанию. Все роли одновременно для каждой задачи не запускаются. Обычно хватает одного-двух исполнителей, максимум — три дочерних агента и действующий лимит клиента. Дизайнер и критик дизайна используют тот же общий лимит.

## Совместимость клиента

Формат проектных ролей и выбора параметров сверен с [официальной документацией Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents) и [справочником конфигурации](https://learn.chatgpt.com/docs/config-file/config-reference), 29 октября 2026. Native TOML закрепляет стандартную модель роли. Для другого уровня используется новый обычный spawn с явными параметрами; нельзя предполагать, что он переопределит фиксированную настройку того же native-типа.

Если инструмент уже перечисляет нужный `agent_type`, можно выбрать эту роль. Иначе рабочий путь — явный объект `spawn` и загрузка инструкции роли. Наличие TOML не доказывает, что текущий процесс перечитал настройки. Проект сохраняет привязки `agents.<role>.config_file`, совместимые с проверенным 27 октября CLI 0.133.0. При той проверке CLI не принимал `agents.default_subagent_*` и глобальный reasoning=max; диагностический запуск использовал временный `-c model_reasoning_effort=medium`. Это история совместимости, а не заявление о версии любого будущего клиента. Глобальные настройки пользователя не меняются.
