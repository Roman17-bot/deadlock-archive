# Архитектура фронтенда

Все экраны сайта находятся в `src/pages/`. Имя каталога совпадает с именем входного компонента, поэтому страницу можно найти без поиска по `features` или общим компонентам.

```text
src/
  app/
    App.tsx                состояние снимка, загрузка/ошибка, диалог методики
    routes.tsx             выбор экрана и ленивые импорты страниц
    useHashRoute.ts        hashchange, текущий маршрут и сброс прокрутки
    page-loading/          каркас первого открытия, ожидание данных и изображений
  pages/
    HomePage/              главная и её секции
    HeroesPage/            прежняя таблица характеристик и приростов
    HeroRosterPage/        выбор героя по портрету и предпросмотр
    HeroStatisticsPage/    статистика матчей и дневные графики
    HeroDetailPage/        досье, способности, история, сочетания и предметы
    MapPage/               карта, карточка объекта и план маршрута
    ItemsPage/             магазин, категории, тиры и ситуационные фильтры
    ItemDetailPage/        характеристики предмета, советы и статистика покупок
    MechanicsPage/         справочник формул, калькуляторы и загрузка каталога
    UpdatesPage/           обновление клиента, история версий, состояние задачи
  features/
    calculator/            формулы, задачи и переключение режимов калькулятора
    hero-calculator/       билд героя, инвентарь, способности и результаты
    synchronization/       состояние и панель точной синхронизации с Pages
    items/                 загрузка данных, ссылки, фильтры и описания предметов
    heroes/                навигация героев, useReference и DemoPlayer
  components/
    layout/                SiteLayout, Header, Footer
    ui/                    StyledSelect, MethodDialog, ArchiveLoading
  hooks/                   useHeroSnapshot, useMediaQuery
  services/                HTTP и обращения к API/статическим данным
  i18n/                    RU/EN, словари и форматирование переводов
  lib/                     небольшие общие функции форматирования
  styles/global.css        общие стили и явный порядок CSS-импортов
```

## Где размещать новый код

- Новая страница: каталог `pages/НазваниеPage/` с входным TSX и CSS; маршрут добавляется в `app/`.
- Секция, нужная одной странице: её `components/`; состояние и эффекты — в её `hooks/`, определения — в `model/` или `model.ts` по объёму.
- Самостоятельная возможность, которую можно подключить к разным страницам: `features/`. Сейчас это калькулятор и синхронизация.
- Общий визуальный элемент: `components/ui/`. Шапка, подвал и каркас — `components/layout/`.
- Загрузка данных: `services/`; жизненный цикл запроса в React — в соответствующем хуке.
- Формула, тип или проверка, которые используют браузер и Node.js: корневой `shared/`, вне `src/`.

Не нужно создавать отдельный файл для каждого выражения или заранее добавлять папки без содержимого. Структура следует реальным обязанностям кода.

## Данные и состояние

`App` получает снимок через `useHeroSnapshot`, передаёт его страницам и принимает новый снимок после успешного обновления. Локальный режим использует ASP.NET Core 10 API (`backend/Deadlock.Api`) и PostgreSQL; GitHub Pages читает опубликованный JSON. Node.js используется для Vite и служебных команд.

При переходе `PageLoadBoundary` показывает каркас нужного экрана, пока не завершатся запросы первого открытия и загрузка изображений этого экрана. Добавляй `usePageDataPending` в хуки таких запросов, а `PendingPageSection` используй для ленивой секции, открытой при входе. Данные и медиа, которые пользователь запрашивает позже через вкладки, фильтры и диалоги, используют состояния своих разделов. Карта пока использует прежний экран загрузки.

Фильтры и сортировка принадлежат реестру, выбранная задача и значения полей — калькулятору. Токен локальной сессии, блокировки и опрос задач принадлежат хукам обновления/синхронизации. Эти состояния не вынесены в глобальное хранилище.

Режим «Билд героя» лениво загружает `features/hero-calculator/HeroCalculator.tsx`: выбор героя и уровня, 12 слотов предметов (до 4 активных), реальные способности и результаты сборки. Переключение сохраняет оба черновика.

Калькулятор формул использует проверенные функции из `shared/mechanics.ts`. React-модель `features/calculator/model/evaluate.ts` преобразует поля формы в вызовы этих функций и результат для интерфейса.

## Досье героев, статистика и карта

`routes.tsx` лениво загружает `HeroRosterPage`, `HeroStatisticsPage`, `HeroDetailPage` и `MapPage` через `Suspense`, отдельно от прежней таблицы `HeroesPage`. Досье использует существующий `HeroAbilities`, расчёт уровня `statsAtLevel`, каталог предметов и статистику покупок; у него нет отдельной копии модели способностей. Переключение «Игра за героя» / «История и связи» локально странице. Уровень влияет на базовые характеристики и параметры способностей, AP-улучшения принадлежат `HeroAbilities`.

`shared/hero-reference.ts` задаёт и проверяет профили/видео и статистику; `heroReferenceApi.ts` читает `/api/hero-profiles`, `/api/hero-statistics` в разработке либо опубликованные JSON в production. `shared/world-map.ts` проверяет карту и рассчитывает условные награды/маршрут; `worldMapApi.ts` использует `/api/world-map` либо `data/world-map.json`. `jsonResource` кэширует валидированные ответы на 60 секунд и объединяет запросы; отмена одного читателя не отменяет общий транспорт. `useReference` хранит загрузку, ошибку и повтор. Профили в выборе/досье и карта используются только при совпадении версии клиента с `HeroSnapshot`; статистика матчей имеет отдельный временной диапазон.

Выбор героя использует общую статистику normal/all за 7 календарных дней: минимум 50% побед — зелёный, меньше — красный, значение также показано числом. Диапазон заканчивается датой `scope.to` в UTC, даже если последние дни не содержат наблюдений. `aggregateHeroStats` суммирует победы и матчи, а не усредняет дневные проценты. Экран статистики предлагает неделю, месяц и год, отдельный выбор режима и выбор ранга только для ranked. Поддержаны все обычные матчи, ranked, unranked, Street Brawl и 11 ранговых групп ranked. Имена RU/EN и локальные иконки рангов заданы в `shared/hero-ranks.ts`. Ранг — средний значок матча, не индивидуальный ранг игрока. Неделя/месяц используют уже загруженные данные; год лениво загружает один объявленный файл через `loadHeroHistory`. Без годового файла доступны сохранённые дни. Доля выборов — матчи героя / сумма выборов всех героев; это не доля уникальных матчей. Отдельная статистика для точной версии клиента отсутствует (`sourceClientVersion: null`); технические пояснения не занимают публичную страницу.

`chart-model.ts` и `Trend.tsx` используют реальные дневные строки и общий календарный диапазон. Вертикальный масштаб каждого графика показывает небольшие изменения; рядом подписаны минимум и максимум. Постоянная серия остаётся горизонтальной, отсутствующие даты/значения разрывают линию. Изменение в процентных пунктах сравнивает первый и последний день с наблюдениями; точность подписи адаптируется без «-0». Кнопка графика открывает дату, значение и число матчей при фокусе/наведении/касании, стрелки перемещаются между наблюдениями, Escape закрывает подсказку. Подсказка через portal позиционируется над реальной точкой и следует за прокруткой. Текстовый процент остаётся доступен без SVG. Обёртка `StatisticsTable` показывает стрелки столбцов только при горизонтальном переполнении; вертикально таблица прокручивается со страницей.

У статистики тот же предел ширины1920px и адаптивные боковые поля, что у таблицы характеристик. Шапка использует общую типографику реестра; общий счётчик выборов убран, действительный диапазон дат показан один раз. Графики растут с180до220px на широких экранах, подписи границ имеют собственные поля сверху/снизу. По последнему выбору пользователя изменение отображается кратко со знаком `%`: это прежняя разница конечного и начального процентов, а не относительный рост. Title и доступное описание указывают оба значения. Дневная линия сохраняется полностью; неделя показывает дневные маркеры, месяц — последний действительный день каждого7-дневного интервала от начала периода, год — последний действительный день каждого UTC-месяца. Наведение и клавиатура доступны для всех дней, выбранная точка рисуется дополнительно. Меняется количество кругов SVG, не числа и не линия. Поиск имеет одну внешнюю рамку фокуса. Общий порядок навигации: главная, герои, предметы, карта, механики, обновления.

`AppRoutes` выводит `HeroNavigation` один раз в общем `hero-navigation-shell` перед содержимым любого раздела героев. Контейнер1920px с одинаковыми полями обеспечивает одинаковую ширину вкладок в характеристиках, списке, статистике и досье, независимо от ширины их содержимого. У страниц больше нет собственных копий навигации. В статистике обычные точки имеют радиус3,25, выбранная —4,5; вертикальные поля SVG8px, padding строк4px и графики шириной220px уменьшают высоту строки на широком экране примерно до93px без изменения дневного path.

`DemoPlayer` — native dialog с видео по конкретной способности/атаке, poster, управлением воспроизведением и указанным отрезком; выход возвращает фокус к инициатору. Когда подходящего проверенного клипа в профиле нет, диалог показывает «Видео пока нет». Ссылка на источник сама по себе не превращается в видеодемонстрацию.

Карта предоставляет категории объектов, смену подложки, поиск по типу/клетке, выбор через список, масштабирование и перемещение мышью/клавиатурой. Подложки тоннелей меняют изображение; они не фильтруют объекты по этажу, поскольку этаж неизвестен. `FarmRoute` считает введённую последовательность после заполнения времени переходов и зачистки; количество существ и доступность подтверждает пользователь. Неполная награда остаётся неизвестной. План учитывает первое появление и известное последнее очищение/возрождение; соединительные линии показывают порядок точек, не проходимый путь. Нет поиска оптимального маршрута, навигационной сетки или предсказания действий противника. Фильтры, выбранный объект и маршрут хранятся в состоянии страницы и не сохраняются между переходами.

## Стили и совместимость

CSS страницы или самостоятельного компонента лежит рядом с ним. Существующие общие импорты остаются в `global.css`; новые страницы выбора героя, статистики и карты импортируют свои CSS локально. Общие стили досье, навигации и видеодиалога подключены через `features/heroes/HeroNavigation.tsx`. Имена классов и адаптивные правила сохранены. Перемещение CSS не должно менять приоритеты каскада.

Ссылки `#/`, `#/heroes`, `#/heroes/roster`, `#/heroes/statistics`, `#/heroes/<slug>`, `#/map`, `#/mechanics`, `#/updates`, `#/items`, `#/items/<slug>` и параметры героя работают на GitHub Pages. `#/heroes` сохраняет прежнюю таблицу характеристик; выбор и статистика доступны через `HeroNavigation`. Досье пересоздаётся при смене slug. Параметр `#/mechanics?hero=<slug>` открывает билд выбранного героя. Неизвестный hash сохраняет поведение главной страницы. Фильтры предметов записаны в параметрах ссылки; подробнее — в [items.md](items.md).

## Проверка изменений

```sh
npm test
npm run typecheck
npm run data:check
npm run data:verify-publication
npm run build
```

Для изменений организации кода используются существующие пользовательские регрессии и сравнение вида до/после на компьютере и телефоне. Для новых функций добавляются проверки поведения на соответствующей границе. Приватные снимки экрана и диагностические материалы находятся в `outputs/` и `work/` и не публикуются.

Страница HeroRosterPage теперь также использует ширину1920px. HeroShowcase.tsx отвечает за изображение выбранного героя, именную табличку, четыре способности и действия. Общая для списка и досье карта src/features/heroes/hero-art.json содержит только пути художественных ресурсов и цвет оформления, без игровых характеристик; новые герои без этих ресурсов используют портрет. WebP и игровые SVG надписей лежат в public/assets/roster/heroes. Иллюстрации подготовлены отдельно от обновления числовых данных, поэтому их автоматическая смена при патче не заявляется. Каталог способностей загружается через существующий useAbilities/jsonResource и повторно используется калькулятором/досье. Шансы победы сохраняют прежний расчёт normal/all за7дней; из публичной шапки убраны повторные технические пояснения.
По уточнению пользователя витрина HeroShowcase монтируется только при ширине от1101px через существующий useMediaQuery. Её хуки профилей/useAbilities находятся внутри компонента, поэтому на телефонах и узких экранах эти JSON и крупные арты не запрашиваются. Поиск, ссылки карточек и винрейты остаются; CSS отдаёт папке одну колонку.
